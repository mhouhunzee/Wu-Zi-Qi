# 五子棋训练性能分析

## 当前性能
- **速度**: 2.0 it/s (每局游戏)
- **GPU**: NVIDIA GeForce RTX 5060 Laptop GPU
- **CUDA**: 12.8

## 瓶颈分析

### 1. 规则检查开销 (主要瓶颈)
在 `model.py` 的 `get_action` 方法中，每次选择动作都要执行：
- `_check_winning_move`: 遍历所有合法位置，模拟落子检查是否获胜
- `_check_blocking_move`: 同上，检查是否需要阻挡
- `_check_open_four`: 检查活四
- 再次检查对手活四

每次检查都涉及 Python 循环和多次棋盘复制操作。

### 2. 神经网络推理
虽然使用了 CUDA，但：
- 每次只推理一个状态 (batch_size=1)
- 模型较小，GPU 利用率可能不高

### 3. 文件 I/O
每局游戏都打开文件追加写入日志，造成频繁的磁盘操作。

### 4. 训练数据收集
`play_game` 中收集每一步的状态，使用 Python 列表操作。

## 优化建议

### 立即优化 (可能提升到 5-10 it/s)

1. **减少规则检查频率**
   - 只在 epsilon-greedy 选择模型时才进行规则检查
   - 随机探索时直接随机选择，不做规则检查

2. **批量推理**
   - 收集多个状态后一次性进行神经网络推理
   - 而不是每步都推理

3. **延迟日志写入**
   - 缓存多局游戏的日志，批量写入
   - 或者使用单独的线程/进程写入

4. **使用 Numba/JIT 加速规则检查**
   - 将规则检查部分用 Numba 加速

### 深度优化 (可能提升到 20+ it/s)

1. **并行环境**
   - 使用多个环境并行进行对局
   - 收集足够数据后再批量训练

2. **C++/CUDA 扩展**
   - 将规则检查和环境逻辑用 C++ 或 CUDA 实现

3. **异步训练**
   - 使用 Experience Replay Buffer
   - 分离数据收集和训练过程
